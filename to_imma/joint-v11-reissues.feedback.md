## 3. Два вопроса по семантике оценки (решений о калибровках не просим; нужен ваш ответ «by design» или нет)
3.1 **Migration delta NBIS ≫ ожидаемого.** NBIS v1.0.3 против v1.0.2: медиана CAGR 5Y +20.7 → +35.1 %, P(loss>30 %)
    10.4 → 0.7 %, ES5 −0.75 → −0.03, медианная стоимость Y5 164 → 289 млрд. Разложение на копиях (100k): тот же файл с
    принудительной schema_version 1.0.1 воспроизводит старое (+20.8 %); файл без ACCELERATOR — те же +35.1 %. То есть
    вся дельта — смена hard_switch → parity_gated_linear_blend, вклад нового драйвера ≈ 0. В контекст-пакете
    parity-gated описан как «Δ 4 п.п.». У NBIS на Y5 базы оценки: crossover_bridge 81 %, multiple 9 %, fallback 2 %,
    blend 7 %; медиана parity margin Y5 0.30. У NVDA дельта умеренная (+22.0 → +23.0 %, ES5 −0.16 → +0.05), Y5: multiple
    62 %, bridge 25 %, blend 13 %.
3.2 **Доля bridge-базы на Y5 у зрелых компаний.** По всем нормативам на схеме 1.0.2 (2.3.2, spec 1.1.3): MSFT bridge 52 %
    / multiple 32 %, META 67 / 19, NET 61 / 26, ETN 61 / 19, PLTR 46 / 44, LLY 33 / 48, ASML 32 / 52, CRWV 61 / 14 (+15 %
    fallback), HOOD 24 / 62. Это было и в принятых прогонах 24.09, магнитуду показала миграция NBIS. Вопрос: ожидаете
    ли вы, что у компаний с положительным FCF на Y5 большинство путей оценивается через crossover_bridge, а не через
    FCF_multiple? Если да — просим одну фразу в Conditional MC (следующая редакция), почему так задумано; если нет —
    это вопрос к правилу parity (blend_width 0.04, порог зрелости) — тогда просим нормативное уточнение, движок
    подправим. До ответа результаты считаем нормативными как есть.
3.3 Для сведения: SPCX v1.1.2 — единственная калибровка, оставшаяся на схеме 1.0.1 (hard_switch); после миграции
    NBIS/NVDA она одна на legacy-семантике в портфельной смеси. Заказ миграции SPCX — на ваше усмотрение после 3.1–3.2.

3.4 **ScenarioConcentration при одном adverse-сценарии.** По §7 B_s = max(0, −ES5Impact_s), концентрация = max B_s / Σ B_s
    по non-BASE. CHIP_COLD_WAR у нас даёт ES5Impact > 0 (нагрузка 0), поэтому вся нагрузка на TAIWAN_SEIZURE и концентрация
    = 100 % при любых вероятностях и любых весах — лимит ≤ 60 % (Optimizer v1.0 §3) нарушен по определению и не различает
    портфели. Просим правило: (а) лимит применяется только при ≥ 2 сценариях с положительной нагрузкой, иначе
    «не применимо», либо (б) нормировать нагрузку на Σ по всем сценариям включая BASE-остаток, либо ваш вариант. До ответа
    лимит в оптимизаторе не применяем, значение показываем.
