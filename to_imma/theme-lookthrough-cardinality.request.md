## 2. Заказ
2.1 **Сквозные доли тем (Theme_Lookthrough)** — расширение MPC-входов (MPC schema v1.1 или отдельный файл `theme_exposure_v1.0.yaml` на
    компанию, на ваш выбор): для каждой бумаги доли по темам (AI_COMPUTE, SPACE, CONNECTIVITY, DEFENSE, HEALTHCARE, …) по выручке и по
    EBIT/капзатратам за базовый период, с происхождением `verified_fact` из сегментной отчётности (10-K/10-Q сегменты; SPCX: AI revenue /
    AI capex / Connectivity operating margin уже в KPI), `derived_fact` при пересчёте, `model_assumption` там, где сегмент не раскрыт
    (с правилом: не раскрыто → доля по умолчанию 100 % основной теме, пометка). Правило сложения на уровне портфеля: тематический вес =
    Σ w_i · share_i,theme; для политики владельца — базовая дата 21.09.2026 и сравнение суммы темы «до/после». Связь с driver_exposure_vector
    (ординальные ±2/±1): он остаётся входом MPC; доли — для тематической концентрации и политики; просим правило согласованности (SCN/MPC-
    проверка: драйверы темы с ±2 должны соответствовать доле ≥ порога). Валидация: MPC-REF-… или новая группа THM-001…
2.2 **Риск перекрёстного субсидирования и дисциплины распределения капитала** — норматив (раздел Company Artifact / Dozor или отдельный
    `Capital_Allocation_Risk_Rules_v1.0`): (а) KPI сегментного уровня, которые надо отслеживать у многопрофильных компаний: доля капзатрат
    сегмента против доли выручки/EBIT, маржа сегмента, число кварталов отрицательного EBITDA сегмента при растущей доле капзатрат,
    детальность раскрытия (число сегментов, перегруппировки); (б) -X- триггеры с порогами (model_assumption, пороги — к владельцу):
    например «убыточный сегмент получает > X % капзатрат N кварталов подряд», «сегмент переупакован / раскрытие сокращено»; (в) правило
    оценки по частям (sum-of-the-parts) как диагностика в калибровке: сумма сегментных оценок против рыночной капитализации, дисконт
    конгломерата как показатель с порогом предупреждения; (г) короткий обзор лучших практик (конгломератный дисконт, внутренний рынок
    капитала, look-through у управляющих) — 1 страница для глоссария хоста. Первое применение — SPCX (сегменты AI / Connectivity / Space);
    для NVDA/MSFT/META/ETN — только доли п. 2.1.
2.3 **Лимит числа бумаг и минимальный вес позиции в оптимизаторе** — нормативная формулировка в Optimizer v1.1: `positions_min` / `positions_max`
    (6…8, owner_judgment), `min_position_weight` 3 % NAV (бумага либо ≥ 3 %, либо 0), фиксированные ETF и кэш вне счёта; место в порядке
    допустимости (§8.1 части A) — структурные ограничения владельца; правило отчёта: варианты «6 / 8 / без лимита» рядом с метриками и
    потерей медианы/ES5 за счёт лимита (цена ограничения). Движок реализуем мы (portfolio_optimizer 1.2.0); просим норматив и порядок
    приоритетов с потолками/общей причиной/сценарными гейтами.
2.4 **Полный текст Portfolio_Optimizer_Specification v1.1** — «полный текст + дельта»: ваш addendum партии 10 (сценарные гейты, S_cond с
    B_s > 0, концентрация 60 → warning / 70 → hard по решению владельца) + п. 2.3 + принятый v1.0 хоста (пришлём файл v1.0 по запросу, если
