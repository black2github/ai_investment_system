# Шаблон финального блока «для дозора» (общий, для любого обсуждения с LLM)

Назначение: в конце обсуждения компании или стратегии попросить LLM выдать итог по этой схеме.
Тогда онбординг в дозор сводится к переносу и проверке, а не к интерпретации переписки.
Версия 1, 17.09.2026. Составлен по двум примерам (SpaceX, WAR-ECONOMY) и одному дозакрытию
(ИИ-инфраструктура). Уточнять по мере накопления примеров.

## Вводная для LLM (вставлять перед шаблоном)

Итог этого обсуждения будет передан агенту, который отслеживает события и присылает уведомления.
Агент проверяет только конкретное: цену, дату, число в отчёте, факт с источником. Сформируй
финальный блок строго по схеме ниже. Правила: каждая строка триггера содержит число и источник
проверки; действия — с числами (процент позиции или портфеля); без «следить внимательно» без
метрики; тикеры с биржей; по-русски, без картинок; чего нет — «неизвестно, проверить: <где>»,
не придумывать.

## Схема

A. РЕШЕНИЕ
Дата обсуждения. Горизонт. Ритм пересмотра.
Таблица: Компания | Тикер и биржа | Статус (покупать / наблюдать / идея / отклонено) | Целевой вес % | Обоснование в одну строку

B. ТЕЗИС ПО КОМПАНИИ (для каждой со статусом покупать / наблюдать)
Тезис в 2–3 фразах. Что ломает тезис — 1–3 проверяемых условия.

C. ТРИГГЕРЫ
Таблица: ID | Компания | Класс (цена / дата / событие) | Условие с числом | Источник проверки | Действие с числом | Окно (с… по…) | Приоритет
ID: <ТИКЕР>-P-NN (цена), -C-NN (дата), -E-NN (событие).

D. ВХОД И ВЫХОД
Таблица: Компания | Уровень входа (цена или мультипликатор) | Схема (разово / транши: сколько, шаг) | Уровни фиксации | Условие полного выхода | Дедлайн тезиса

E. СЦЕНАРИИ (если обсуждались)
Название | Признак наступления (какая новость, источник) | Вероятность | Действия по каждой позиции с числами

F. КАЛЕНДАРЬ
Дата | Событие | Компания | Что смотреть | Действие при ожидаемом / неожиданном исходе

G. ПРЕДПОСЫЛКИ К ПРОВЕРКЕ
Факт | Значение из обсуждения | Где проверить (первоисточник)

H. ЛИСТ ИДЕЙ (статус idea)
Компания | Тикер | Дата идеи | Цена на дату | Условие возврата к идее

I. ОТКЛОНЕНО
Компания | Причина

J. ОТКРЫТЫЕ ВОПРОСЫ
Что не закрыто и почему; что решает владелец.

## Как это соотносится с реестром дозора

| Раздел | Куда попадает |
|---|---|
| A, B | `portfolio/<тикер>/thesis.md`, meta реестра |
| C | `triggers.yaml` — переносится почти дословно, class ← класс, action ← действие |
| D | триггеры класса price (уровни входа/фиксации/выхода) + meta.position_plan |
| E | сценарии (пакет действий); до появления сущности — event-триггер с текстовым действием |
| F | триггеры класса calendar |
| G | `state.json.pending_verification` → разовые проверки по первоисточникам |
| H | триггеры со статусом idea + ретро-дозор |
| I | не переносится, фиксируется в thesis.md как история |
| J | вопросы владельцу до активации |
