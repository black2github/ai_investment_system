## Пробел: входы MPC для SPCX
Модель SPCX (states/kpis v1.3, RV, MC) создавалась до появления MPC, поэтому у SPCX нет `driver_exposure_vector` v1.0
(16 исходных драйверов), `failure_modes` с `common_cause_id` и `driver_interpretation`. Патч v1.1 дал только 16 новых полей.
Просьба выдать `SPCX_mpc_inputs_v1.0.yaml` в формате секции `mpc_inputs` партий 1–5 (полный вектор из 32 драйверов,
failure modes с общими причинами SPACE-кластера — RKLB/ASTS уже используют LAUNCH_VEHICLE_DEVELOPMENT_FAILURE,
LAUNCH_OPERATIONS_FAILURE, GOVERNMENT_SPACE_BUDGET, SPACE_REGULATORY_RANGE_DELAY — и AI-кластера NBIS/CRWV, поскольку у
SPCX есть ось AI compute).

## План следующего этапа — просьба подтвердить или поправить порядок
Состояние: 14 моделей компаний с подтверждёнными KPI; у SPCX есть калибровки reverse valuation v1.0 и условного MC v1.0;
у остальных 13 — нет. Конвейер MPC требует standalone-распределений (Conditional MC) для каждой компании.
Предлагаемый порядок:
1. **MC v1.1** (как договорились — после теста Flight 14, 23.09): формализация I1–I5, показатели RV_Growth_Gap и
   Price_Expectation_Gap, улучшенный Robustness, пометка bridge_dependent. Одновременно — обобщение движка MC на
   сегменты из калибровки (сейчас движок привязан к трём сегментам SPCX).
2. **Калибровки RV + MC для 13 компаний партиями по 3 по весу NAV**: NBIS, NVDA, HOOD → LLY, META, ASML → RKLB, MSFT, NET →
   PLTR, ETN, ASTS → CRWV. Формат: как `calibration_v1.0` и `mc_calibration_v1.0` SPCX (сегменты выручки, узлы маржи,
   терминальные мультипликаторы, корреляции), с оговоркой: для прибыльных компаний (NVDA, LLY, META, MSFT, PLTR, ETN, HOOD)
   двухфазная траектория маржи D3 не нужна — нужна ваша типовая форма для «зрелая маржа + рост».
3. **MPC-прогоны** после накопления standalone-распределений. По решению владельца сначала фактический портфель
   (14 позиций), затем кандидаты prior Core-10, которых нет в портфеле (AVGO, KLAC, SNPS, CDNS — здесь и парный эксперимент
   SNPS/CDNS), и корзина «ИИ-инфраструктура» (SU, 6506, 6324, CRWD).
4. Portfolio Optimizer и Stability Test — спецификации ещё не выдавались; просьба оценить, что нужно раньше: спецификация
   оптимизатора или калибровки (2), чтобы MPC-прогоны не ждали.

Вопрос по ресурсам: калибровка одной компании у вас занимает заметный объём; если разумный размер партии для калибровок
иной, чем для моделей (3), скажите.
